# ADR-009: Frontend Architecture

## Context
The platform interface requires an engineering-grade dashboard featuring interactive node-graph editors for microservice topologies, real-time streaming telemetry charts, incident timelines, and report viewers.

## Problem
We need a modern frontend stack that aligns seamlessly with our UI/UX design workflow (**Google Stitch**) and rapid prototyping tool (**Vercel v0**), while ensuring type safety and modular component reusability.

## Decision
Adopt **Next.js 14+ (App Router)** with **TypeScript**, **Tailwind CSS**, **shadcn/ui**, **React Flow** (for topology authoring), and **Recharts** (for metric visualization).

## Alternatives Considered
- **Vite + React SPA:** Faster local build times, but lacks native Server-Side Rendering (SSR) for fast dashboard initial paint and requires separate server setups for secure cookie handling and server-side PDF exports.
- **SvelteKit / Vue:** Great performance and ergonomics, but inferior ecosystem alignment with shadcn/ui component primitives, Google Stitch exports, and Vercel v0 generative capabilities.
- **D3.js for graphs:** Extremely powerful, but introduces high imperative complexity compared to declarative React Flow.

## Advantages
- Perfect parity with Vercel v0 and Google Stitch design systems.
- shadcn/ui provides accessible, dark-mode-first, copy-pasteable UI components built on Radix UI.
- React Flow offers high-performance draggable nodes, custom edge routing, and zoom/pan canvases.
- Strong TypeScript end-to-end typing matching backend Pydantic models.

## Disadvantages
- Node.js runtime required for server rendering in production.
- Next.js App Router caching mechanisms require careful configuration.

## Consequences
All frontend screens will consume the versioned REST API defined in `docs/06_api_specification.md` without requiring knowledge of backend internal structures.

## Status
**Accepted**
