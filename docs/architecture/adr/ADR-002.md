# ADR-002: Database Selection

## Context
The platform manages complex relational entities: Tenants, Users, Memberships, Projects, Topologies, Services, Dependencies, Sandboxes, Experiments, Runs, Incidents, and Reports. Data integrity, foreign key cascading, and strict tenant partitioning are critical.

## Problem
We must choose a primary persistent datastore that balances strict relational consistency and referential integrity with the flexibility to store dynamic UI canvas coordinates, environment variables, and semi-structured experiment parameters.

## Decision
Adopt **PostgreSQL 16** using the **asyncpg** asynchronous driver and **SQLAlchemy 2.x** with **Alembic** for schema migrations. High-volume time-series metrics and distributed traces will strictly NOT be stored in PostgreSQL (delegated to Prometheus and Jaeger).

## Alternatives Considered
- **MongoDB:** Flexible document model, but lacks strict ACID multi-table transactional guarantees and foreign key enforcement needed for complex relational topologies.
- **MySQL:** Strong relational database, but JSONB querying and indexing capabilities are less mature than PostgreSQL's GIN indexing.
- **SQLite:** Great for embedded local development, but lacks concurrent write throughput, native network pooling, and multi-tenant isolation required for production.

## Advantages
- Rock-solid ACID transactional integrity for complex infrastructure state mutations.
- Rich JSONB support with GIN indexing for dynamic experiment configurations and React Flow canvas metadata.
- Native asynchronous driver (`asyncpg`) provides high connection throughput.
- Expressive SQL window functions for incident deduplication and temporal queries.

## Disadvantages
- Horizontal write scaling requires manual sharding or distributed extensions (Citus) at massive scale.

## Consequences
All relational entity operations will execute through SQLAlchemy models. Every query touching tenant data must explicitly include `tenant_id` filtering. Telemetry time-series data is explicitly routed away from PostgreSQL.

## Status
**Accepted**
