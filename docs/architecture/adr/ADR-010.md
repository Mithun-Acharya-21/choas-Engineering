# ADR-010: Security and Tenant Isolation

## Context
As a multi-tenant platform executing controlled infrastructure failures, the system must guarantee strict tenant data isolation, prevent lateral movement across Kubernetes workloads, and prevent malicious or accidental disruption of the host cluster.

## Problem
How to establish defense-in-depth across the API, database, messaging, and Kubernetes cluster layers without compromising system performance or developer usability.

## Decision
Implement a multi-layered security architecture:
1. **API Layer:** OAuth2 JWT authentication with RBAC roles (`TenantOwner`, `Engineer`, `Viewer`).
2. **Database Layer:** Multi-tenant row-level scoping: every query explicitly filters by `tenant_id`.
3. **Execution Safety:** Strict prohibition of raw shell/bash commands. Chaos is executed solely via typed APIs (Toxiproxy REST API and Kubernetes API).
4. **Kubernetes Layer:** Namespaces configured with baseline Pod Security Standards (`runAsNonRoot: true`, `readOnlyRootFilesystem`), `ResourceQuota`, and default-deny `NetworkPolicy` blocking cross-namespace traffic and host API access.

## Alternatives Considered
- **Client-Side Tenant Filtering:** Dangerous and vulnerable to authorization bypass bugs. Rejected in favor of backend-enforced dependency injection.
- **Granting Sandboxes Full Kubernetes ServiceAccount Privileges:** Rejected. Sandbox pods receive zero Kubernetes API tokens (`automountServiceAccountToken: false`).
- **Running Chaos via Privileged Container Exec:** Rejected. Executing arbitrary commands inside running containers bypasses audit trails and introduces high security risk.

## Advantages
- Multi-tier defense-in-depth: even if one layer is compromised, subsequent layers prevent lateral movement.
- Zero raw shell execution eliminates command injection vulnerabilities.
- Default-deny networking prevents cross-tenant data snooping.

## Disadvantages
- Requires maintaining explicit NetworkPolicies and sidecar configurations.

## Consequences
Every API endpoint implementation must inject the `CurrentTenant` dependency, and all Kubernetes manifests generated by the platform must enforce non-root security contexts.

## Status
**Accepted**
